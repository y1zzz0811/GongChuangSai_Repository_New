# 树莓派与 STM32 视觉接口协议

**用途**：供视觉组部署、接入和联调。按 STM32 **C6.40** 与本地树莓派程序核对。涵盖任务码、地面编号环、地面物料顶面和原料转盘。协议线上没有版本协商。

## 1. 分工和接线

- **树莓派**负责采图、认目标、验证观测、计算偏差和回包。相机 1 读二维码，相机 2 定位。树莓派给出目标相对夹爪的偏差，动作由 STM32 决策。
- **STM32**负责选择工位和目标，安排停稳、复拍、动作额度、抓放及暂停。电脑上的 CarDebugger 用于发起调试和查看状态，连接的是主控的 **USART1 调试串口**。下面的视觉报文走另一条 **UART5**。

| 信号 | 树莓派 4B | STM32 UART5 |
|---|---|---|
| 树莓派发 → STM32 收 | 物理针脚 8 · GPIO14 / TXD | PD2 / RX |
| STM32 发 → 树莓派收 | 物理针脚 10 · GPIO15 / RXD | PC12 / TX |
| 共地 | 物理针脚 6 · GND | GND |

串口为 **3.3 V TTL、115200、8N1、无流控**。树莓派用 `/dev/serial0`，开启串口硬件、关闭串口登录控制台。二维码与定位共用这一个串口，由双摄程序独占。对调摄像头线后核对设备号，程序默认相机 1 为 `/dev/video0`（640×480），相机 2 为 `/dev/video2`（800×600）。

## 2. 帧格式和字段

报文使用 ASCII、英文逗号分隔、末尾 **LF**（`\n`，0x0A）。接收兼容 CRLF。字段之间不加空格。表里的 `\n` 表示一个换行字节。

| 用途 | STM32 → 树莓派 | 树莓派 → STM32 |
|---|---|---|
| 扫码 | 树莓派见码后主动发送 | `QR,COLORS1+RINGS1+COLORS2+RINGS2\n` |
| 地面编号环 | `VQ,ID,RING\n` | `VR,ID,RING,FRAME,AGE,FWD,LEFT,CRC\n` |
| 物料顶面 | `VQ,ID,RING,TOP\n` | `VR,ID,RING,FRAME,AGE,FWD,LEFT,TOP,CRC\n` |
| 原料盘 | `VQ,ID,COLOR,RAW\n` | `VR,ID,COLOR,FRAME,AGE,FWD,LEFT,RAW,CRC\n` |

RAW 修正后复拍使用 `VQ,ID,COLOR,RAW,DF,DL\n`。DF/DL 是相对本次首次观察位置，夹爪已执行的前向和左向净位移，单位为整数 mm，分别限 ±50 mm、±100 mm。DF = 底盘前向净位移 − M7 伸出净位移，DL = 底盘向左净位移。首次或两轴净位移都为 0 时不带这两项。树莓派把位移加回本帧测到的偏差，以核对同一个场内侧物理停位。RAW 视觉回包依据目标颜色、停稳状态和配置的物料区窗口，不再用主控的抓取容差筛掉偏差；主控收到偏差后负责底盘粗定位和 M7 精定位。所有 VR 回复格式不变。

地面环帧没有 `RING` 类型后缀，表里的 `RING` 字段填写环号。类型字面值 `TOP` 和 `RAW` 必须大写。请求和扫码帧没有 CRC。STM32 的接收行缓冲可容纳 79 字节（不含 LF，使用 CRLF 时 CR 占一个字节）。建议一包一次写完。

| 字段 | 取值和含义 |
|---|---|
| `ID` | STM32 生成的请求号，十进制 **1～4294967295**，请求不加前导零。回复带回同一个请求号。 |
| `RING` | 1～3。地面环要求识别这个编号。TOP 时是主控已经选择的工位标签，视觉只需要在该观察位置定位物料顶面。 |
| `COLOR` | 1 红、2 黄、3 蓝、4 绿、5 黑、6 浅蓝。 |
| `FRAME` | 本次计算中最新一张参与帧的编号，十进制 **1～4294967295**。 |
| `AGE` | 树莓派准备发送时，最早一张参与帧距采集的时间，向上取整到 ms。用本机单调时钟计算，两端无需校时。 |
| `FWD` / `LEFT` | 两个有符号整数，单位 **µm**，单轴协议范围 **−500000～500000**。前、左为正，后、右为负。正数直接写数字，例如 `12000`，不加 `+`。 |
| `CRC` | 两位十六进制 CRC-8，树莓派使用大写。STM32 接收大小写。 |

**坐标例子**：`FWD=-5000, LEFT=12000` 表示目标相对夹爪参考点**后 5 mm、左 12 mm**。两个分量独立传输，STM32 据此决定动作。画面像素坐标 `u` 向右、`v` 向下，不能直接当作车体偏差。地面环、TOP、RAW 均以相机 2 **原始画面中心**定义夹爪参考，800×600 时取 `(399.5, 299.5)`。

### 2.1 CRC 与联调样例

CRC-8 多项式 `0x07`，初值 `0x00`，输入和输出均不反射，末尾异或 `0x00`。校验内容从开头的 `VR` 到最后一个数据字段为止，**不含** CRC 前的逗号、CRC 字段、CR 和 LF。标准校验向量 `123456789 → F4`。

```python
def crc8(data: bytes) -> int:
    crc = 0
    for byte in data:
        crc ^= byte
        for _ in range(8):
            crc = ((crc << 1) ^ (0x07 if crc & 0x80 else 0)) & 0xFF
    return crc

body = b"VR,42,3,972,1137,-667,3333,TOP"
packet = body + f",{crc8(body):02X}\n".encode("ascii")
```

下面每行单独以 LF 结束。每组回复中的 ID 应按实际请求填写，改任何一个字段后重新生成 CRC。

| 模式 | 请求示例 | 回复示例 |
|---|---|---|
| 地面环 | `VQ,41,2` | `VR,41,2,956,485,-5000,12000,77` |
| TOP | `VQ,42,3,TOP` | `VR,42,3,972,1137,-667,3333,TOP,5C` |
| RAW | `VQ,43,6,RAW` | `VR,43,6,998,690,700,-1400,RAW,26` |

### 2.2 二维码

完整任务码是 **四组、每组三位**。依次是第一批取料颜色、第一批放置环号、第二批取料颜色、第二批环号。例：

```text
QR,156+123+516+231
```

STM32 要求每批的三个颜色来自 1～6、批内不重复；两批的颜色集合相同，顺序可以不同。每批的环号都是 1、2、3 的一个排列。同一批内，颜色和环号按三位的顺序逐个对应。树莓派的基础格式校验较宽，现场制码按上述 **STM32 规则**执行。

相机 1 连续三张识别结果只有同一个合法格式的任务码时发送。树莓派会抑制重复发送；二维码离开画面约 1 s 后再出现，可重新发送。同一码要重扫时，要让树莓派重新发送，同时按主控流程清除旧任务码或重新进入扫码阶段。电脑日志里的 `QR received: ...` 或 `qr status` 用于确认主控侧接收，UART5 不回扫码 ACK。主控锁定任务码后忽略新的扫码帧，定位仍可按请求正常交换。

## 3. 请求生命周期和拒绝条件

1. STM32 同时只挂起一个定位请求。机械臂进入观察姿态并停稳后发 `VQ`。下一次复拍有一个新的 ID。
2. 树莓派收到 `VQ` 后丢弃已有帧和随后一张可能缓存的帧。收集三张有效新帧，前后、左右各自的极差均须 **≤2 mm**。各轴取中位数，最后从 mm 换算成 µm。缺失检测、离群、数据过期时继续取新帧。
3. 有效结果只回一次。树莓派等新请求。未找到目标、缺少该模式配置、超时或观测不稳定时不发 `VR`。协议没有 NACK、全零占位、持续发送坐标或树莓派自行补发的分支。两轴恰好对准时才合法输出实际测得的零。
4. STM32 拒绝请求号、目标号、类型、字段数、CRC 或数值范围不符的回复。消费时再加上从主控收到回包到消费的本地耗时，检查是否过龄。消费了第一份有效回复后关闭请求。视觉失败由主控停止当前流程，调整或重试由主控发新请求。

| 模式 | 树莓派单帧最大帧龄 | 准备回包时最早参与帧最大帧龄 | 树莓派处理窗口 | STM32 等待窗口 |
|---|---:|---:|---:|---:|
| 地面环 | 1000 ms | 1500 ms | 11 s | 12 s |
| TOP | 1250 ms | 3000 ms | 8 s | 9 s |
| RAW | 650 ms | 1500 ms | 89 s | 90 s |

地面环的处理和等待窗口从每次停稳后发起定位请求开始计时，空爪定位、移动后复测、持料复核分别计时。独立部署的树莓派程序需要把编号环请求处理窗口设为 11 s。STM32 消费的总帧龄上限沿用表中的最早参与帧上限。RAW 还要求**准备发送时最新帧 ≤350 ms**、**主控收到后 ≤150 ms 内消费**，合格后可直接抓取的回包还须满足实际剩余停留时间。串口异常时主控可能打印 `QR RX error; send LF then retry.`，它指的是 QR 和视觉**共用的 UART5**，即使正在做 TOP 单件也可能出现。

## 4. 各场景的目标和动作

| 模式 | 视觉侧要交付什么 | 主控怎样用 |
|---|---|---|
| 地面编号环 | 按指定编号定位黑色环的内缘圆心。编号需确认，圆心毫米换算需有足够的内缘点。 | D 粗加工放料、E 首层放料，以及单件首层放置。空爪对准后取料，持料到位再复拍。 |
| TOP | 按 **60 mm 顶面离地高度**识别物料顶边。现版在零点附近搜索，先用底部外轮廓筛选，再拟合顶缘。TOP 不再识别物料颜色或环内数字。 | 地面单件抓取、D 粗加工取回、E 第二层码垛。码垛定位的是第一层**已经放下的物料顶面**。正式路线的目标环来自任务记录。 |
| RAW | 按 **盘面 80 mm、顶面 140 mm**定位，识别并跟踪请求色。目标停在场内侧且满足抓取窗口时可回报定位偏差。已在抓取容差内的回复还须满足剩余停留时间。 | 空爪面向转盘，在下降前发请求。超差时主控先修正横移和 M7，停稳后用新 ID 复拍，合格后才抓取。 |

首次 RAW 请求重置跟踪。若目标准备时已经静止，等待下一轮看到它移动并重新停下。当前停稳判据是先出现同向的连续位移，再有至少 4 个样本、覆盖 1 s、各轴极差不超过 1 mm；断帧或位置跳变会重置跟踪。颜色用顶面中心小块的 OpenCV 8 位 Lab 通道中位数，只有**唯一匹配请求颜色**才继续。剩余停留时间按最近一次确认移动的时刻保守估计，回包需要覆盖从下降到抬离的最坏耗时，再留 **350 ms**。

超差回包后，主控使用带 DF/DL 的 RAW 请求复拍。若颜色相同、上一次已成功回包且仍有足够剩余停留时间，树莓派继承该停留周期的确认时间，在新姿态下重新验证至少 1 s 的停稳观测、三帧毫米偏差及场内侧窗口；不复用旧图像或旧偏差。新测位置加上 DF/DL 后，需与本周期最初记录的停位相距不超过 10 mm。超出该范围、物料丢失或跟踪中断时，必须重新观察运动与停稳。若请求未携带 DF/DL，则仍按新周期处理（包括净位移回到零且省略字段的情况）。新入口的转盘单件整次上限为 480 s，单次 RAW 请求主控限 90 s、树莓派限 89 s。地面单件整次上限为 120 s。

### 4.1 主控动作接口与额度

| 项目 | 当前行为 |
|---|---|
| 对位成功条件 | RAW 转盘抓取前后、左右绝对偏差均 **≤5 mm**。TOP 和编号环模式前后 **≤2 mm**、左右 **≤5 mm**。两轴均通过才能下降或放置。 |
| 单件地面抓取、首层放置、第二层码垛 | 空爪对位最多修正 **4 轮**。单件空爪的底盘粗调后必复拍，再按新的偏差做 M7 精调。M7 目标超过起点 **±20 mm** 时，优先尝试底盘前后补位。地面、转盘的单件横移额度均为 **0～100 mm**，网页预填 **100 mm**。前后补位额度均为 **0～30 mm**，网页预填 **0**。首层和码垛卡片也可填写 0～30 mm 的前后补位额度，非零需确认无障碍。持料期间仅复拍确认。 |
| 正式路线 D/E | 上电修正额度均为 0。用电脑调试串口的 `route2 limits D E M7` 设置，范围分别是 **0～20 / 0～10 / 0～20 mm**。D/E 是底盘横移额度，M7 是相对名义位置的补偿额度。主控同时检查工位边界与机械状态。 |
| 方向 | `LEFT > 0` 对应车体向左修正。机械臂转向物料的观察姿态中，M7 伸出朝车尾，前方偏差为正时 M7 回缩。是否执行及执行多少由 STM32 根据当前剩余误差决定。 |
| 持料复拍 | 首层和码垛放置均复拍。持料时超差会停止下降，主控不执行持料横移追赶。 |
| 原料盘 | 超差时最多修正 4 轮。转盘单件通过开始命令设置本次横移和前后额度，并要求场景已确认 `obs none`。正式路线的横移用 `route2 rawlimit MM`（0～20 mm，上电为 0），不启用前后补位。M7 在单件中相对实测起点限 ±20 mm，正式路线用 `route2 limits` 的 M7 额度。抓起抬离后 M7 恢复原位，入槽并回到运输姿态后，转盘单件底盘按指令位移反向归位。地面单件底盘停在夹取位置。 |

搜索范围描述视觉从哪里找目标，动作额度描述底盘和机械臂可以移多少。增加 `--top-search-mm` 不会放宽限位。

## 5. 树莓派部署和参数

树莓派工作目录通常为 `/home/string/Documents`。运行双摄前退出其它占用相机或串口的程序，确保有相机设备访问权限。当前入口使用 Python 3、OpenCV、NumPy、pyserial 与 Tk，并调用 v4l2 工具。交接至少带上：

- `dual_camera_recognition.py`、`dual_camera_preview.py`、`qr_camera1.py`
- `numbered_ring_detector.py`、`numbered_ring_templates.png`、`ring_metric.py`
- `route2_vision.py`、`stacking_vision.py`、`raw_pickup_vision.py`
- 当前观察姿态的环定位 JSON，以及启用 RAW 时实测的原料配置 JSON

### 5.1 标定与姿态

**C6.39 主控的 M6 工作顶点为 167 mm。** 现有 `ring_metric_Z184_image_center.json` 的相机姿态来自旧的 **Z=184 mm** 采图。两者是各自的机械参考坐标，均不是相机距地面高度。相机随升降、回转、伸缩运动；**联调前在实际观察位置复核毫米值**，姿态变化造成尺度或方向偏差时，重新提供对应的平面标定。文件名的 Z 数字不会改变程序使用的投影。当前串口没有传输相机姿态或物料高度的字段。

标定文件字段包括 `image_size`、`camera_matrix`、`dist_coeffs`、`ground_marks` 和 `diameters_mm`。`ground_marks` 按 `[u, v, 前向坐标, 左向坐标]` 提供；联调 TOP/RAW 使用 **10 mm/标定坐标单位**。地面 1～3 号环的最内圈内缘直径按实测 **50 mm**，地面环换算用该直径恢复尺度。联调 TOP/RAW 目前按物料顶缘直径 **30 mm**、底部直径 **50 mm**计算。旧的 `zero_pixel` 会被忽略，零点采用原始画面中心。

### 5.2 原料 JSON

`raw_config.json` 是**原料转盘 RAW 模式的现场参数**，不是相机镜头标定文件，也不是深度学习模型。相机几何标定仍由独立的 `ring_metric_*.json` 提供。RAW 配置用来确定场内侧可抓取停位、转盘停留时间预算和颜色范围；没有有效配置时，程序仍可启动并运行 QR、地面环和 TOP，但会拒绝伪造 RAW 结果。项目目前没有随代码提供通过现场验证的配置，请从实际抓取姿态采样后填写。

`--raw-config` 需要以下字段：

| 字段 | 格式及限制 |
|---|---|
| `pickup` | `[u,v]`，相机 2 原图中**场内侧有效停位**的顶面中心像素，投影到 140 mm 平面。 |
| `window_mm` | 圆形抓取窗口半径，>0 且 <29 mm。窗口中心的两轴偏差绝对值分别加该半径，均须 <29 mm。RAW 搜索半宽固定 30 mm。 |
| `minimum_stop_ms` | 实测最短可靠停留时间，≤120000 ms。 |
| `pickup_clear_ms` | 发起下降至夹紧并抬离的最坏耗时，>0。最短停留必须比此值多 **超过 1350 ms**，代码还会对每次观测检查剩余时间。 |
| `lab_ranges` | 对象须包含字符串键 `"1"` 到 `"6"`。每项为 `[[L低,a低,b低],[L高,a高,b高]]`。通道范围 0～255，各通道下限严格小于上限。应在实际照明和阴影下分开采样，尤其核对蓝/浅蓝与黑色/阴影。 |

窗口中心和夹爪零点分别配置。旧 RAW 配置中的 `zero` 会被忽略。若盘高或物料高度变化，独立预览可传入高度，但当前联动入口的 RAW 高度仍固定为 80/140 mm，改变联动几何需调整树莓派联动实现并重新验收。

### 5.3 启动命令

以下 `OBS` 指向**已在当前工作姿态复核过的文件**。示例沿用目录已有文件名，仅在姿态和实测换算相符时使用。RAW 命令里的 `raw_config.json` 需按上一节准备。

```sh
cd ~/Documents
OBS=ring_metric_Z184_image_center.json

# 统一双摄串口入口：二维码 + 地面编号环 + TOP + RAW
python3 route2_top_center.py --ring-metric "$OBS" --raw-config raw_config.json

# 地面单件抓取预设。也可以显式传入当前标定文件。
python3 route2_top_center.py --pickup-test --ring-metric "$OBS" --top-search-mm 50
```

统一入口按请求自动选择：普通 `VQ,ID,RING` 使用编号环；`TOP` 使用地面 60 mm 顶面；`RAW` 使用托盘 140 mm 顶面并按颜色跟踪。TOP 搜索半宽默认 **50 mm**，`--top-search-mm` 可设 5～100 mm，前后、左右各应用一次。TOP/RAW 处理期间暂停无关的编号环识别，避免它占用相机 2 的计算时间。RAW 最多等待 89 秒，TOP 等待 8 秒，地面编号环等待 11 秒。独立预览只运行其中一条，也不打开串口：

```sh
# 地面物料顶面与码垛对位
python3 stacking_vision.py --calibration "$OBS" --height-mm 60 --search-mm 50

# 原料盘，默认盘面 80 mm、物料高 60 mm
python3 raw_pickup_vision.py --calibration "$OBS"
```

预览程序支持空格保存无叠字原图、`Q` 退出。`--image 原图.png --output 标注图.png` 可用于离线复现。原料预览可用 `--pickup U V --window-mm 半径` 查看窗口判定；串口联动的参数仍从 RAW JSON 读取。纯扫码或纯相机预览入口不会应答定位请求。

## 6. 主控侧联调与验收

在 CarDebugger 进入「视觉与定位 → 视觉单件测试」。准备三轴参考、解锁、S1 夹爪参考和 S2 托盘输出。抓取入口还需确认场景无障碍，逐项核对树莓派和 UART5、空爪姿态与空槽、物料与下降行程、底盘和夹爪的扫掠范围。如下命令发到**主控调试串口**，新单件入口在网页上确认一次后自动执行。地面抓取独立使用 TOP，不需要扫描任务码。

| 单件测试 | 主控命令示例 | 视觉目标 |
|---|---|---|
| 地面物料 → 托盘 | `route2 single ground 1 20 20` | 空槽 1，累计横移和前后补位各限 20 mm，TOP 标签固定为 1 |
| 托盘 → 首层编号环 | `route2 single ring 1 2 20 20` | 从槽 1 取料放在 2 号环，地面环模式 |
| 托盘 → 第二层 | `route2 single stack 1 2 20 20` | 从槽 1 取料放在 2 号工位已摆好的第一层物料上，TOP |
| 原料转盘 → 托盘 | `route2 single raw 1 6 10 20` | 目标浅蓝，入槽 1，横移限 10 mm，前后补位限 20 mm，RAW |

网页仅保留统一的视觉单件入口。已有串口脚本的 `route2 pickup SLOT SIDE [FWD]` 继续兼容，FWD 省略时前后额度为 0。正式路线的地面环、TOP 用 `route2 vision on` 开启，RAW 须同时开启 `route2 rawvision on`。两项上电默认关闭，支持 `off`，用 `route2 status` 核对。新单件入口自身选择对应视觉模式。CarDebugger 的 `@r2single`、`@r2state` 等是主控到电脑的调试遥测。

建议按这个顺序验收：

1. **独立预览**。固定小车和观察姿态，在中心放物料，核对拟合轮廓贴合顶缘。分别移动目标到前、后、左、右的已知位置，核对数值与符号。地面和盘面分别测。先核对像素中心，再核对毫米偏差。
2. **串口联调**。核对每次操作对应一种 `VQ`，树莓派一条有效 `VR`，ID、目标、类型和 CRC 一致。保留树莓派终端日志和主控日志。无目标、错号、错误 CRC 或超龄应被拒绝。
3. **实物单件**。先做地面抓取，再做首层与码垛，检查空爪和持料复拍。原料模式另外验证错色、到站即静止、正常转入停稳和错过窗口。记录原料最短停留时间、动作最坏耗时，以及视觉成功率和延迟。
4. **正式路线**。核对实测横移净空、M7 行程、场界和物料放置顺序后，设置适当额度再开相应视觉模式。

| 现象 | 优先查什么 |
|---|---|
| 树莓派没有 `VQ RX` | 主控是否进入视觉阶段；程序有没有开启串口定位；PC12 → GPIO15 方向和共地。 |
| `target mode not configured` | TOP 是否按联动入口启动；RAW 是否加载了有效 JSON。 |
| `NOT CONFIRMED` / `MM UNAVAILABLE` | 前者是编号环未确认，后者是已找到编号但几何换算无效。目标物料顶面须另看 TOP 日志或独立预览。 |
| `NO MATERIAL OUTLINE` / `WEAK TOP EDGE` / `NEAR SEARCH LIMIT - RECENTER` | 检查目标高度和观察姿态、底缘/顶缘对比度、遮挡、搜索范围及初始摆位。 |
| `three-frame spread exceeds 2 mm` / 帧龄超限 | 查是否停稳、拟合跳变、计算耗时、相机读帧或 USB 带宽。 |
| 树莓派有 `VR TX`，主控超时 | 查 GPIO14 → PD2、CRC、请求号、目标号、类型、LF 以及过龄。 |
| 主控已打印 `fwd=... left=... um` 后停止 | 已收到定位结果，继续核对动作额度、收敛次数、持料复拍或电机动作故障。 |
